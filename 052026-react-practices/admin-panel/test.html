SƏNƏDLƏŞDİRMƏ: Cross-Functional BPMN Swimlane Proseduru

Təqdim olunan çox-zolaqlı (multi-lane swimlane) biznes proses strukturuna uyğun olaraq, Mobil Bank Referral Mexanizminin tam funksional arxitekturası yenilənmiş və çarpaz funksional zolaqlar şəklində vizuallaşdırılmışdır. Bu ssenari müştəri təcrübəsi, interfeys, backend məntiqi və daxili bank sistemləri arasındakı asılılıqları tam göstərir.

1. Çarpaz Funksional BPMN Diaqramı (Cross-Functional Swimlanes)

(Customer)

2. Sistem Modulunun Spesifikasiyası (SRS Analizi)

2.1. Funksional Ssenarilər və İstisnaların İdarə Edilməsi

Biznes Qaydası Sistem Davranışı (Ssenari) Gözlənilən Texniki Nəticə (Response)
Mövcud olmayan kod Müştəri verilənlər bazasında qeydiyyatda olmayan mətn daxil etdikdə. HTTP 400 Bad Request; Xəta mesajı: "Daxil edilən referral kod yanlışdır".
Deaktiv kod yoxlanışı Kampaniya müddəti bitmiş və ya inzibatçı tərəfindən deaktiv edilmiş kod tətbiq olunduqda. HTTP 400 Bad Request; Xəta mesajı: "Bu referral kod artıq aktiv deyil".
Özünə tövsiyə qadağası Sifariş verən şəxsin customer_id göstəricisi kodun sahibinin ID-si ilə üst-üstə düşdükdə. Sistem əməliyyatı dondurur. Xəta: "Müştəri öz referral kodundan istifadə edə bilməz".
Təkrar bonus əleyhinə filtr Eyni məhsul müraciəti (Application ID) üçün təkrar icra mesajı qəbul edildikdə. İdempotentlik mexanizmi işə düşür, tranzaksiya rədd edilir, mükərrər ödənişin qarşısı alınır.

2.2. Verilənlər Bazası Arxitekturası (Relational Design)

BPMN axınında göstərilən dövlət və status keçidlərini təmin edən relyasiyalı cədvəl strukturu:

Cədvəl (Table) Sütunlar və Tiplər İndekslər və Məhdudiyyətlər (Constraints)
referral_codes id (UUID), customer_id (VARCHAR), code (VARCHAR), status (ENUM), created_at PRIMARY KEY (id), UNIQUE (customer_id), UNIQUE (code), INDEX (status)
referral_rules id (INT), product_type (VARCHAR), referrer_amount (DECIMAL), referee_amount (DECIMAL) PRIMARY KEY (id), UNIQUE (product_type)
referral_transactions id (UUID), application_id (VARCHAR), used_code (VARCHAR), status (ENUM), updated_at PRIMARY KEY (id), UNIQUE (application_id), Foreign Key (used_code) references referral_codes(code)
